# Input2.6.1 native SSE and axis production

The native owner is `sadx-native/src/sse_math.{hpp,cpp}` plus `input_mod_axes.{hpp,cpp}`. It executes source arithmetic, with no emulated-game runtime or host atan2/sqrt. It requires an explicit MXCSR and raw signed16 axes. Captured Intel Ultra PC MXCSR and physical OS input behavior remain unavailable. InputState now requires sample_tick(SseContext&, InputModAxesConstants&): it advances the raw keyboard ramp once, calls this recovered two-stick helper before arbitration, and returns per-stick source metadata plus the selected software MXCSR status. Both keyboard profiles use recovered SSE normalization; the immediate profile remains explicitly distinct because it changes the raw ramp. Apple controller axes enter a separately named NormalizedControllerSnapshot boundary and use an explicit native SSE policy, not original signed16 SDL production. The integrated keyboard path is raw keyboard ramp → this owner → prepared Input Mod pad → actual WriteAnalogs and magnitude hook → GetAnalog; the original raw-controller backend remains missing.

## Arithmetic contract and provenance

Caller-selected MXCSR includes retained incoming low-six sticky flags, rounding bits13..14, DAZ6, FTZ15 and masks7..12. Reserved high bits are rejected. SSE exceptions are immediate; old unmasked sticky flags do not retroactively trap. A failure commits architectural exception status and exposes no operation destination. Contexts are thread-owned and scope/restore the shared SoftFloat TLS environment; x87 precision/control does not select SSE rounding. Only scalar low-lane values are modeled; packed operations in these routines have zero upper source lanes.

The backend is pinned Berkeley SoftFloat3e revision `a0c6494cdc11865811dec815d5c0049fba9d82a8`, BSD3-clause license, retained under `third_party/softfloat_sse/`. Its absent-symbol arithmetic closure uses 8086-SSE NaN propagation. Shared common-NaN converters and raiseFlags are byte-identical between 8086 and8086-SSE; exact comparison digests are retained. The x878086 specialization/TLS/state/source files were not changed or duplicated. Upstream source notices and COPYING.txt are retained. Input Mod logic was independently reconstructed from the pinned binary with its pinned MIT source as corroboration; the existing Input Mod MIT notice remains under licenses/.

Intel's primary [Floating-Point Reference Sheet2.13](https://cdrdv2-public.intel.com/786447/floating-point-reference-sheet-for-intel-architecture.pdf) specifies destination-first NaN priority, DAZ replacement, precomputation exception priority, working precision/tininess, masked FTZ and unmasked underflow behavior. [SDM Volume2B MINSS pages4-31/4-32](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2b-manual.pdf) specifies second-operand selection for NaN/equalzero, preserving source SNaN bytes, and invalid including QNaN. Conversion instructions preserve actual narrowing payload behavior; CVTTSS2SI ignores RC and does not raise denormal-operand #D. No source arithmetic is contracted into FMA.

## Verification and remaining evidence

Strict optimized and UBSan native source tests passed, covering round directions, NaN priority, signed zero/MINSS, DAZ/FTZ, exact tiny underflow traps, exception priority, CVTT invalid/truncation, thread boundaries, x87 environment isolation, controller deadzone/radial/singular cases, keyboard ramp/diagonal/release/opposing raw transitions and partial source stores. Build outputs were created only under `/private/tmp/sadx-sse`; shared Makefile/archive artifacts were left to their owner.

The isolated actual DLL instruction verifier evaluated controller72,960 and keyboard36,096 cases across16 explicitly selected masked MXCSR controls (4RC ×2DAZ ×2FTZ): **109,056 outputs, zero mismatches**. MXCSR differed93,104 times: Unicorn2.1.4 keeps helper exceptions in sse_status while the visible MXCSR word stays unchanged. Both raw counts and examples remain retained; full-state `passed` is false. This does not demonstrate that the updated mods loaded in Windows, physical-controller equivalence, keyboard OS cadence or source frame timing.

The separate scalar probe evaluated312,112 cases. It retained5,076 value disagreements and all status disagreements, with `passed=false`. Every value disagreement fits a source-confirmed emulator limitation:320 destination-priority NaN cases,4,220 FTZ cases,536 MINSS/DAZ cases; zero unclassified mismatches. Retained Unicorn source explains why: `input-mod-unicorn-softfloat-specialize.inc.c` lines436 onward choose x87 NaN rules for i386; `player-input-unicorn-fpu-helper.c` update_mxcsr_status line1607 applies FTZ to fp_status although SSE operations in `input-mod-unicorn-ops-sse.h` lines607 onward use sse_status; FPU_MIN lines617 onward compares DAZ-transformed inputs but returns original raw operands. These emulator limitations have not been copied into native semantics. Retained files are evidence only, not production dependencies. Their source digests and native-file digests are in `input-mod-axes-validation.json`.

Physical hardware tests, actual Windows runtime snapshots and source instruction exception probes on the user's Intel Ultra remain required. Native keyboard half-press, camera recenter, D-pad, controller priority/demo and full Windows poll phases remain separate missing owners, not silently simplified here. This module is not evidence of complete input or gameplay support.
