# Physical controller capture investigation

The user reports both controllers connected to this Mac. Passive IORegistry evidence independently confirms USB identities: Nintendo Switch 2 Pro VID `057e`, PID `2069`, and Microsoft Xbox Series X gamepad VID `045e`, PID `0b12`. A separate Apple `GamePad-1` synthetic HID node has VID `045e`, PID `028e`; it is not interchangeable with the physical Xbox identity. See `connected-controller-hid-summary.json` and its retained source plist. Enumeration does not establish delivered physical input or gameplay compatibility.

## Read-only capture owners

`sadx-native/src/mac_controller_probe.mm` uses nonexclusive IOHIDManager input callbacks and live GameController profiles. It opens only its own manager, changes/restores process-local background monitoring, and closes its owned resources. It never sends HID output reports, pairs devices, changes calibration, plays rumble, or writes controller settings. The explicit source-produced axes constant asset and selected software MXCSR are diagnostic sample inputs, not observed Windows FP state. Its 20 Hz samples are diagnostic; they are not game ticks or a 63 FPS measurement.

`mac_gc_only_probe.mm` separately observes GameController without opening IOHID devices. `mac_hid_access_probe.mm` calls only `IOHIDCheckAccess(kIOHIDRequestTypeListenEvent)`; it never requests or changes access.

`mac_controller_tester.mm` is the repair for the windowless receiver: a real foreground AppKit application with a visible window, a main-queue live-controller callback and a 30 Hz common-mode timer. It polls the live extended profile directly and also passes a stable `[controller capture]` to the existing production adapter. `isSnapshot=false` describes the retained live controller, not the adapter's captured sample. Its Info.plist enables controller user interaction and advertises ExtendedGamepad. The arm64 `.app` was compiled, plist-validated, ad hoc bundle-signed and signature-verified. Parent opened it through LaunchServices with GUI authorization; no second concurrent tester should be started.

## Observations and uncertainty

* Plain headless GameController enumeration initially returned no controllers both inside and outside the command sandbox. This does not prove unsupported hardware.
* The first passive IOHID open inside the command sandbox returned `0xe00002e2` (not permitted). The corresponding escalated nonexclusive open succeeded. Both physical devices then satisfied Apple's `supportsHIDDevice` predicate. That predicate alone is not a live profile or delivered-event guarantee.
* The outside-sandbox listener subsequently received a live Xbox extended profile. The existing native adapter accepted its neutral snapshot. No Switch 2 GameController object appeared in the observed interval.
* The GC-only background-enabled probe subsequently also enumerated the Xbox. Therefore the evidence does not isolate IOHID open as necessary; background monitoring and prior process/system state are confounded.
* The passive Switch descriptor contains report ID 9, four 12-bit axes with logical range 0..4095 and 21 buttons. Successful cached `IOHIDDeviceGetValue` calls returned zeros; these are neither a calibrated neutral position nor proof of an input report. The physical Xbox node exposed no GenericDesktop/Button elements in that enumeration.
* `controller-user-ready.jsonl` is the parent's terminal 300-second windowless listener. IOHID open/close succeeded, but it retained only the initial neutral Xbox snapshot and zero HID input changes despite the user's reported button/stick attempts. The user explicitly did not test Xbox triggers. The first Switch attempt used its console connection; a later retry was reported, still with no captured changes. Those user actions are reported facts; they are not captured controller events.
* The foreground `.app` log `controller-visible.jsonl` begins with `app_active=true`, a connection notification and accepted live neutral Xbox profile. It ended through the normal root-owned application lifecycle with `background_restored=false`, at elapsed1,005.337s. The user asked to disconnect and hardware testing was deferred. The single requested Xbox A hold/release confirmation is explicitly unknown; callbacks remain zero. No further presses, captures or tester launches were requested or performed.
* Host/headless access check reported `Granted=0`; the foreground application's own identity reported `Unknown=2`. Access is identity-dependent. This difference does not itself establish a GameController permission cause, and no permission request was made.

These observations establish USB presence and an accepted neutral Xbox GameController snapshot, not working physical controls, verified Switch support, original SDL raw-axis parity, in-game action bindings, or successful native gameplay.

## Primary authorities

Apple [background monitoring](https://developer.apple.com/documentation/gamecontroller/gccontroller/shouldmonitorbackgroundevents), [controller enumeration](https://developer.apple.com/documentation/gamecontroller/gccontroller/controllers%28%29), [controller interaction plist](https://developer.apple.com/documentation/bundleresources/information-property-list/gcsupportscontrolleruserinteraction), [supported controller profiles](https://developer.apple.com/documentation/bundleresources/information-property-list/gcsupportedgamecontrollers), and [IOHIDCheckAccess](https://developer.apple.com/documentation/iokit/3181573-iohidcheckaccess?language=objc) were inspected alongside the installed SDK headers. `IOHIDCheckAccess` is declared in `IOKit/hidsystem/IOHIDLib.h`.

The upstream SDL Switch 2 driver is pinned at commit `930cd0dbf8d1b6fdc5b91711d8d71542c1df0960`, retained as `sdl-switch2-controller-driver.c`, from [the primary source](https://github.com/libsdl-org/SDL/blob/930cd0dbf8d1b6fdc5b91711d8d71542c1df0960/src/joystick/hidapi/SDL_hidapi_switch2.c). Its USB initialization includes bulk-interface commands, calibration reads, rumble enable and unknown-purpose commands. None has been executed here. Wholesale initialization is outside the understood minimal-input scope. A future temporary input-stream handshake must first identify exact interface/endpoints, purpose, ownership and cleanup; parent reviews the concrete source before execution. `switch2-usb-interfaces.json` currently establishes registry interface nodes, not endpoint descriptors or handshake sufficiency. No SDL driver code was incorporated into the native executable.

Raw OS/hardware input equivalence and the updated native Windows reference capture remain separate outstanding work. The diagnostic foreground window is not the native game deliverable.
