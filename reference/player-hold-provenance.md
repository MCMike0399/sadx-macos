# Native held-object flag query

Frozen implementation: `sadx-native/src/player_hold.hpp/.cpp`, `tests/player_hold.cpp`, `tests/native_player_hold_probe.cpp`, and `tools/verify_original_player_hold.py`. This reconstructs actual **0x43b9c0** as an integer-only flag query. It makes no exec calls or stores, moves no object, and performs no floating-point instructions. Returning zero is permitted only by a recovered branch with available facts; unknown objects or required resource links produce typed failures.

## Authority and source identity

Original executable SHA-256 remains `6b0937caa0151287c182fcd8cd02b89ea464bd33a13a081c1220fa791f24cd74`. Retained Hopper dossier is `_reference/sadx/gameplay/hold-object.json`, EvidenceID `ev_aa103833c803a5c4ab1f403c66349cf1331ce5b73d07db9855e8ddfbd70bddbb`. The complete source instructions and embedded jump tables were independently read with Xcode's llvm-objdump and the pinned PE reader. Parent owns the queued independent Ghidra recovery; no duplicate provider/session was opened by this agent.

The source reads taskwk.flags(+4). Flag0x800 selects global player-work lookup at **0x3b3cdf0** indexed by the whole player-index byte(+8). There is no index bounds check in this routine, and no null guard for that player-work pointer. The runtime therefore requires an explicit lookup; an unknown table entry and a known-null pointer are distinct failures. It must not replace the lookup with the PSetPosition caller's physics object just because indices usually agree.

The held branch reads playerwk+0x68, then tests held Task.exec(+0x10), motion_work(+0x24), primary_work(+0x20) and primary collision reference(+0x38), in that order. Observed null held task, null exec, the actual DestroyTask callback identity0x40b570, null motion work, null primary work or null collision pointer return zero. Native `TaskScheduler::destroy_callback` is that callback's compiled owner; no source address is cast to a native callback and no exec is invoked.

When those guards pass, actor ID byte primary-work+2 is read **before** the character(+9) out-of-range return. An attached **Task::primary_state** supplies its authoritative **PlayerTaskState::task_id_at_2**; an unknown live ID fails at0x43ba34 and never falls back to stale arena bytes. Without a typed view, the actual TaskWorkArena owns byte+2. The collision reference remains owned by TaskWorkArena even when the typed scalar view is attached. Native tasks come from real scheduler factories with known exec input and known-null initial work handles; opaque/unobserved source tasks must remain an unknown held reference instead of becoming fabricated native null fields.
